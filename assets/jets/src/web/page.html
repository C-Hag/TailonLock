Tailon Lock Hangar

Eight original jets for the game: real-world layouts, computed flight performance, low-poly models and a working cockpit for each. Review copy, not in the game yet.

Cockpit

Click the cockpit, then fly: ↓/S pull, ↑/X push, ←→ or AD roll, Shift/Ctrl or +/− throttle (above 100% is afterburner), G gear, F flaps, Q weapon, M master arm, P demo autopilot. On touch, drag in the outside view like a stick. Click displays to change their pages.

Fleet comparison

All numbers come from the same point-mass flight model at combat mass (60% internal fuel, listed weapons). The cockpits run that model live.

Model files

One .glb per jet in assets/jets/. Flat-shaded triangles, one material per colour, 700 to 1,800 triangles each. Axes: +Y up, +Z nose, +X left wing, metres, origin near the centre of gravity. Nodes: airframe, canopy, stores (hide when fired), and on the NF-24 wing_L/wing_R that rotate about Y for sweep.

For the C port

The game reads them with its own GLB reader (src/core/glb.c): positions and normals only, no textures, so the software rasterizer needs just a colour per primitive. Each file's root node carries its id in extras. Flight data for every jet is in jets_data.json.

Carrier file

cvn90.glb (same axes, waterline at y = 0, deck at y = 20.5 m). Its root extras hold the deck data the game needs: catapult start and end points, the three wire positions, glide slope, hook touchdown point, lens position and parking spots. carrier_game.js has the same in the game's format.

For the browser game

jets_game.js holds the same meshes in the game's own {v, f} format with X mirrored to the game's axes (+X = right wing), plus the flight numbers, so a jet-select screen can drop them straight in.
