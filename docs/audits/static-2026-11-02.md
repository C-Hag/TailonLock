# Static audit, 2026-11-02

Every C file of the game, the platform layers (macOS, Linux, Windows) and the C tools, through four checkers, before
anything was fixed; then every finding looked at, the real ones fixed, and every checker run again.

- **Base:** `33b480c` (claude/own-platform-mac). **Fixes:** branch `claude/static-audit-1102`, 22 commits on the base.
- **Every finding, one per line, with its verdict:** [static-2026-11-02/findings.tsv](static-2026-11-02/findings.tsv)
  (tool, file:line, the tool's severity, the check, the tool's message, and "real bug, fixed in <commit>" or "not a
  bug: <why>"). These are the results of the run before any fix, with duplicates removed.
- **The gate that keeps it so:** `tools/static`, in `certify plat`'s P0, with the reasons in `tools/static.supp`.

## Not bugs: the groups

Each group's reason is in `tools/static.supp`; findings.tsv has the reason on every line.

- **Annex K** (465 scan-build, 1,197 clang-tidy: "use fprintf_s"): Annex K is optional in C11, missing on glibc
  and macOS, and the game is C11 only.
- **Unchecked return values** (cert-err33-c, 903): printf-family logging and tool outputs. The writes that can lose
  a player's data now go through `plat_save_end`, which checks them (fix 14).
- **Narrowing conversions and signed bit operations** (about 1,200): float maths in a float game, and colour packing
  on values never negative.
- **Float loop counters** (26 scan-build, 29 clang-tidy): integer steps, which are exact in float, or probes and
  geometry that set no count. The one that set a count was fix 15. Turning the others into integer loops would move
  the sampled values by a rounding and could change pictures, for no gain.
- **Style** (cppcheck const-correctness, variable scope, parameter names, shadowing that -Wshadow -Werror already
  rules out): not about behaviour.
- **One by one:** about 400 findings were read in the code (every one outside the groups above), each with the line that rules it out: the drone always
  exists in drone mode (game.c:61, 319-320), arrays filled before they are read, indices clamped first, NaN checks
  written as `x == x` on purpose, D3D12 states that are flags. They are scoped to their files in tools/static.supp,
  so a new finding of the same kind elsewhere fails until someone looks at it.
- **Threads:** every getenv, strtok and localeconv runs on the main thread or only reads; nothing in the game calls
  setenv or setlocale (concurrency-mt-unsafe, 43).

## Valgrind (Linux arm64 VM, gcc 14.3)

On the base: memcheck clean on all 14 ctest tests, all 100 headless start/quit runs and a short audit (0 errors, no
definite or indirect leak). helgrind and drd each reported one race, on `audio_run` in plat_linux.c: an
`atomic_bool`, so not a race, but neither tool understands C11 atomics and each stopped there. The flag is now also
read and cleared under the sound mutex (787fb32), which both tools can follow; no change in behaviour.
On the fixed code (787fb32, the same Linux files as the head): memcheck clean on 14 of 14 ctest tests, 100 of 100
start/quit runs and the audit; helgrind (500 s) and drd (332 s) found no race in the sound storm.

## The gate

- `tools/static`: cppcheck with the three sets of defines and clang-tidy on each build's compile database; every
  finding must be fixed or have its line in `tools/static.supp` with a reason. A missing tool fails, and a reason
  that no longer matches anything is reported, so the file stays the truth.
- `certify plat` P0 runs it on its own build (and on the MinGW one where there is a cross compiler).
- On Linux, P1 runs test_plat_core under memcheck, P2 starts and quits the game 20 times under memcheck, and P4 runs
  helgrind and drd over the sound storm (32aab9e).

## What this does not cover

- Out-of-memory paths are fixed by reading, not by tests: there is no allocation-failure hook to drive them.
- The Linux platform files went through clang-tidy 21 (the distribution's own) on the Linux build in the VM: 3,378
  findings; 113 of them the same findings as on macOS under their CERT alias names, 7 more looked at one by one (all
  not bugs, reasons in tools/static.supp): 0 open.
- Windows was checked by cppcheck's Windows defines and by clang-tidy on the MinGW build; MSVC was not used.
