# Safe C pass, 2026-11-02

The rules are in [docs/SAFE_C.md](../SAFE_C.md). This is what applying them to the whole codebase found and
changed. Branch `claude/safe-c`, on 1c7b67a (the static audit's head).

## The banned calls

| Call | Before | After |
|---|---|---|
| `strcpy`, `strcat`, `sprintf`, `vsprintf`, `gets`, `alloca`, variable-length arrays | 0 | 0 |
| `scanf` `%s` / `%[` without a width | 0 (every one has a width) | 0 |
| `atoi`, `atof`, `atol` | 62 | 0: `safe_int`, `safe_num` |
| `strtok` | 2 | 0: `safe_token` |

`safe_int` and `safe_num` read the number at the start of the text exactly as `atoi` and `atof` did, so every valid
input reads the same; text with no number gives the caller's default, and an overflow is held to the range instead
of being undefined behaviour. `tools/static` now fails on any banned call; no line in tools/static.supp can
excuse one. A planted `sprintf` in a test file was caught; a banned word in a comment or a string is not.

`-D_FORTIFY_SOURCE=3` (detected; 2 otherwise; not in Debug or sanitizer builds) on every GCC and Clang build. Clean
with -Werror on macOS (Apple clang), Linux (gcc 14.3 and clang 21) and Windows (llvm-mingw clang 23); the Windows
exe still needs only Windows' own DLLs.

## -Wconversion and -Wsign-conversion (a report)

956 warnings on the macOS build, none of them a narrowing to a smaller integer type or a double to float (the code
already casts those on purpose):

- **794 int to float** (727 `int`, 39 `const int`, and 28 `size_t`/`long`/`uint64_t` to `double`): every int here is a
  game quantity (a pixel, a count, a score, a frame number) far below 2^24, where float is exact; `double` holds
  every size and time in its 53 bits. One was worth changing: gpu.c's frame step divided a `uint64_t` counter rate
  by a float. The rates in use (24 MHz, 10 MHz, 1 GHz) are all exact in float, but it is now done in double.
- **17 enum to float**: enum values used in float maths, on purpose.
- **145 sign conversions**, read one by one: 141 safe, each with the line that keeps the value in range (pixel loops
  from 0, clip rectangles that start at 0, sizes from fb_resize, byte assembly of little-endian fields, enums that
  every writer validates, buffer lengths that only grow); **1 real**: intro.c's haze band indexed the frame at a
  negative row when the script's `y0` is below the top (fixed, 3945576). On the way: audit.c's BMP reader left out the
  rows' padding in its size check (a short file was read past its end), and livepilot read a frame into a failed
  malloc and divided by zero on an empty one (fixed, 3945576).
